# Audiobookshelf connection and downloads

## A profile can have several addresses

The listener enters addresses explicitly. A Home address might be `https://books.home.example/audiobookshelf`. A Tailscale address might be `https://books.example-tailnet.ts.net/audiobookshelf`. Accept a port and a path prefix. When the scheme is omitted, default to `https`; require an explicit choice before using `http`. Normalize once: lowercase the scheme and host, drop a default port and keep a single trailing slash. Preserve the prefix when constructing requests. Reject embedded credentials, fragments and query strings in base URLs.

**Pairing.** On first sign-in, store the account ID and available stable server/library identifiers. Pair each additional address through its own sign-in and compare the authenticated account and server identity. Audiobookshelf v2.38.0 exposes no stable server instance ID: `GET /status` returns the app name, `serverVersion`, `isInit`, language, `authMethods` and `authFormData`. Compare the account ID, which is the server’s user ID, and a known accessible library ID instead, display the match and ask the listener once to confirm the alias. A mismatch cannot become an automatic route. Keep each address’s authenticated session scoped to its exact origin and base path. An alternate address must never receive another address’s refresh token.

**Automatic mode.** After a network change, select the first reachable, paired address in the listener’s priority order. Probe only when network work is requested. Use a short bounded timeout per address (initial target 1.5 seconds), reuse the working address on that network, and clear the cached choice when the network changes. A reachable Tailscale address works like any other configured route. This design does not need to read Wi-Fi names or manage the VPN. Manual mode pins a chosen route and names it in a connection error.

**Address changes during a transfer.** Removing, disabling or reordering an alias never cancels or fails an in-flight transfer. When its serving address disappears, the job keeps its staged files and moves to Waiting for connection. It resumes through the next reachable paired address only after the source-identity reconciliation under [Safe continuation across routes](#safe-continuation-across-routes). Complete verified files are reused when the refreshed manifest still identifies the same source. A partial file continues only on the same URL and revision with a saved validator and known length. Otherwise it restarts from byte zero unless byte identity is proven. The job waits rather than fails while no enabled address remains. Removing every alias preserves the profile, books and progress.

**Transport and failures.** Prefer HTTPS with normal certificate validation. That validation accepts the system’s certificate authorities and the ones the listener has installed on the phone.

An HTTPS address whose certificate fails validation gets no request. Read the presented certificate from a handshake that is then abandoned, and show the unrecognized-certificate copy from the [product brief](01-product.md#copy-and-recovery) with the SHA-256 fingerprint of that whole certificate, not of its public key alone, in the colon-separated form that `openssl x509 -noout -fingerprint -sha256` prints, so the listener can compare it with the server’s. When the listener chooses Trust this certificate, store the fingerprint with the address. From then on that origin, and no other, accepts exactly the certificate with that fingerprint. The match takes the place of chain, expiry and host-name validation there: a self-signed certificate often names another host than the address the listener types, and only the holder of that certificate’s private key can complete a connection with it. When the origin later presents another certificate, stop using the address, show the certificate-changed copy with the new fingerprint, and send nothing until the listener trusts the new one. An address that used to pass normal validation and now fails it shows the certificate-changed copy too. The Trust action exists only in connection setup and Server addresses. Everywhere else an address in either state counts as unreachable: automatic mode skips it, and a transfer served through it waits as it does when its address is removed. When no paired address answers and a changed certificate stops at least one of them, Library, the launch and a Download tap show the certificate-changed copy for that address in place of the unreachable-server copy. Library and a Download tap show it without the fingerprint and with an action that opens Server addresses. A launch that opens connection setup shows it there with the fingerprint and its Trust action. Where a denied local-network permission blocks another address at the same time, the first of the blocked addresses in the listener’s priority order decides which copy shows. A confirmation never extends to another origin, to a redirect or to an HTTP address.

Support an explicitly enabled HTTP endpoint for installations that need it. Explain the cleartext tradeoff when pairing and store the opt-in per origin rather than per network, so it persists across network changes. Enforce the exact opt-in origin in the HTTP client even if Android needs an application-level cleartext allowance for runtime hosts. Restrict redirects to the approved origin and path. Never follow a TLS downgrade or send credentials to an unpaired destination.

A timeout or disconnected network can trigger failover for a safe read or transfer. A mismatched pairing disables that address and surfaces a specific error. Refresh a 401 once using the credentials for that origin. A 403 download denial is a permission decision and ends the request. On Android 17, where the local-network permission applies, check the permission before contacting an address that the platform classes as local network, because a blocked connection otherwise looks like a timeout. Request it in context, when such an address is first paired or used, and explain which address needs it. While it is denied, connection setup and Server addresses show the local-network copy from the [product brief](01-product.md#copy-and-recovery) for that address, never the unreachable-server state. When no paired address answers and the denial blocks at least one of them, Library, the launch and a Download tap show that copy for the first blocked address in the listener’s priority order, in place of the unreachable-server copy. Its action asks again, or opens system settings once the system no longer shows its prompt. Automatic mode skips the address and keeps using the others, and a transfer served through it waits as it does when its address is removed. Permission denial leaves Downloaded usable.

## Server contract to pin in M0

The listener’s server runs 2.38.x, so pin the reference release v2.38.0 (2026-11-17) and capture sanitized fixtures, including its file identifier and authorization behavior. The minimum is 2.26.0, the first release with the access/refresh token flow below; its database migration is `v2.26.0-create-auth-tables`. Read `serverVersion` from `GET /status` before sign-in. On an older server show the server-too-old copy from the [product brief](01-product.md#copy-and-recovery) instead of falling back to its non-expiring legacy token. The server repository includes an OpenAPI document, but in v2.38.0 it describes 31 paths and, of the operations below, only the library and catalog lists. Read the others from the server source (`server/Auth.js`, `server/Server.js` and `server/controllers/`) and from the captured fixtures. The older API reference is useful for payload examples, and the maintainers’ JWT notes describe the mobile headers. Favor the contract observed on the pinned server when they differ.

| Operation | Request shape to verify | Client responsibility |
|---|---|---|
| Probe and sign in | `GET /status`, `POST /login` with mobile header `x-return-tokens: true` | Use status for reachability, server version and `authMethods`. When `local` is absent, show the password-sign-in copy from the [product brief](01-product.md#copy-and-recovery) instead of a password form. Use authenticated data for pairing. Read the user’s `id` and `username`, `user.permissions` and the current access/refresh token pair. |
| Renew session | `POST /auth/refresh` with `x-refresh-token` | Serialize refresh per address, persist rotated credentials together and retry an eligible read once. Default lifetimes are 1 hour for access tokens and 30 days for refresh tokens (server variables `ACCESS_TOKEN_EXPIRY` and `REFRESH_TOKEN_EXPIRY`), so a long download crosses access-token expiry. Read `exp` from the access token and refresh shortly before it, and send every new file or range request through the same refresh path. A replaced refresh token stays valid for 10 minutes by default, so a crash between rotation and the local write, or a refresh whose response is lost, recovers only inside that window. After it the address needs a new sign-in and shows the session-expired copy. |
| List libraries | `GET /api/libraries` | Filter to accessible book libraries. Persist the chosen library per profile and restore it on relaunch. Handle zero accessible book libraries with an explicit empty state, and several with a selector defaulting to the last choice. |
| List catalog | `GET /api/libraries/{libraryId}/items` with zero-based `page`, `limit`, `sort=media.metadata.title` and `minified=1` | Send a positive `limit` on every page, because an absent or zero `limit` returns the whole library in one response. Walk pages in a stable order, deduplicate IDs, and refresh atomically as described under [Publishing a library refresh](#publishing-a-library-refresh). Offset pages shift when a scan adds or removes items during the walk, and the title sort has no unique tiebreaker for equal titles. Either way an item can be skipped without producing a duplicate. The completeness check of that section catches a walk whose count is off, and a skipped item that the count hides appears on the next refresh. Skip entries whose `media.numTracks` is zero. Cached search by title/author covers all fetched pages. Explicitly indicate when the initial catalog is still filling. |
| Fetch book and cover | `GET /api/items/{itemId}?expanded=1` and `GET /api/items/{itemId}/cover` | Read `media.tracks`: the non-excluded audio files in play order with `startOffset`, `duration`, `ino` and `metadata.size` and `mtimeMs`. Files marked `exclude: true` remain in `media.audioFiles` and never become tracks. Read `media.chapters` (`start`, `end` and `title`, in seconds) and descriptive metadata. Skip ebook-only entries. Request list thumbnails with the cover’s `width` and `format` parameters and `ts` set to the item’s `updatedAt`. Store the original (`raw=1`) with the edition. The cover route needs no token in v2.38.0, so send none. Cover failure is recoverable. |
| Download an original file | `GET /api/items/{itemId}/file/{fileId}/download` | Use the track’s `ino` as the file ID and treat it as a string. Of the routes that serve this file’s bytes on their own, only this one checks the download permission. The track’s `contentUrl` (`/api/items/{itemId}/file/{ino}`) streams the same bytes without that check, so never fetch download audio through it. A denied download is never fetched through another route. Check response integrity. |
| End a session | `POST /logout` with the origin’s refresh token in `x-refresh-token` | The route needs no access token and deletes that session on the server. An access token already issued stays valid there until it expires, within the hour. Revoke the session when reachable and clear the local credential either way. Sign out does this for every paired address, as described under [signing out and in again](#signing-out-and-in-again). Address removal does it for that address and keeps the profile and local books. |

Use a non-admin test account with and without download permission. Login, refresh and `GET /api/me` return the user’s `permissions.download` flag with `librariesAccessible` and `itemTagsSelected`. Show the disabled-download state on details from that flag before any transfer and refresh it with the catalog. Still treat a 403 as final, because an administrator can change permissions at any time. A Play tap on a completed download makes zero playback-session or audio HTTP requests. The app stores per-book progress locally. It does not send listening sessions or progress updates to the server in v1. If a server requires OIDC-only login, show the password-sign-in copy from the [product brief](01-product.md#copy-and-recovery). Native OIDC is outside v1.

### Observed on the reference instance

These observations come from a local Audiobookshelf v2.38.0 instance (`ghcr.io/advplyr/audiobookshelf:2.38.0`) with disposable non-admin accounts and the synthetic fixture books, not from the listener's deployment; what nginx or the listener's settings change there stays an [owner check](06-delivery-and-tests.md#owner-checks). `server-fixture/abs.sh` reproduces the instance, and the sanitized exchanges are in `app/src/test/resources/abs/v2.38.0/`.

- `GET /status` answers without a token with `serverVersion`, `isInit` and `authMethods: ["local"]`.
- `POST /login` with `x-return-tokens: true` returns `user.accessToken` and `user.refreshToken` on the user object, with `user.id`, `user.username` and `user.permissions.download`. Without the header the refresh token goes only into a cookie. The access token lives 3600 s and the refresh token 2 592 000 s (30 days).
- `POST /auth/refresh` rotates both tokens. The replaced refresh token still refreshes immediately afterwards, as the grace period says.
- `GET /api/libraries` returns `{"libraries": [...]}`; an account with no accessible library gets an empty list with status 200. `GET /api/libraries/{id}/items` with `limit=0` returns every item in one page.
- In `?expanded=1`, `ino` is a string. An excluded file disappears from `media.tracks`, which are renumbered, and stays in `media.audioFiles` with `exclude: true` and `index: -1`. The chapter list is not rebuilt after an exclusion, so it can run past the remaining audio; the validation of [chapter map and fallback](05-playback-and-formats.md#chapter-map-and-fallback) handles that.
- A multi-file book without chapter marks gets one generated chapter per audio file; a single file without marks gets an empty list. The chapter rules treat the generated list as no markers.
- The download route answers 200 with `content-length`, `accept-ranges: bytes`, a weak `ETag`, `Last-Modified` and `content-disposition: attachment`, and the body matches the source file. `Range: bytes=1000-` gives 206 with `content-range: bytes 1000-N/M`. The server also answers 206 to `If-Range` with the weak tag, which the client never sends.
- An account without download permission gets 403 from the download route and 200 from the stream route `/api/items/{id}/file/{ino}`.
- The cover route answers without a token. `POST /logout` with `x-refresh-token` answers 200.
- `POST /logout` ends that session: its refresh token no longer renews, even inside the grace period that applies after a rotation.
- `POST /login` and `POST /auth/refresh` share one limiter: by default 40 requests per 10 minutes from one client address (`RateLimit-Policy: 40;w=600`; the server's `RATE_LIMIT_AUTH_MAX` and `RATE_LIMIT_AUTH_WINDOW` change it). The next request gets 429 with `Retry-After` in seconds and `{"error":"Too many authentication requests"}`. Every client behind one address shares the budget. A 429 is neither wrong credentials nor an expired session: sign-in shows the too-many-sign-ins copy from the [product brief](01-product.md#copy-and-recovery), and a renewal keeps the stored session and fails its request as temporarily unavailable, so Library shows the unreachable state with Retry.
- On the Android 17 emulator (API 37, `CE2A.260420.051.A3`), an app targeting SDK 37 without `ACCESS_LOCAL_NETWORK` cannot open a TCP connection to the host alias `10.0.2.2` (a 10.0.0.0/8 address); with the permission it can. The Android 14 emulator connects without any permission. Whether a Tailscale address on the listener's phone is classed as local stays an [owner check](06-delivery-and-tests.md#owner-checks).

### Signing out and in again

Sign out, in Settings, asks once for confirmation. It then sends the logout request to every paired address that answers and deletes every local credential, whether or not a server answered. A session that could not be revoked expires on the server by itself. Sign out keeps the profile, its addresses, the cached catalog, every edition and all progress. Transfers in progress or queued move to Waiting for connection and keep their staged files. While signed out, Library shows the session-expired copy with Sign in, and Downloaded and playback work as before.

A later sign-in on any paired address must return the profile’s account ID. Another account is refused with the different-account copy from the [product brief](01-product.md#copy-and-recovery), creates no profile and changes nothing on the phone. Once the profile’s account has signed in on an address, that address works again, and waiting transfers continue after the usual source-identity reconciliation. Each other address needs its own sign-in, as it did when it was paired. To use another account or server, the listener clears the app’s data in Android’s settings.

### Publishing a library refresh

Scope each refresh to its profile and library. Give the attempt a refresh generation ID, separate from any edition’s generation, and stage its pages under that ID. While it runs, browsing and search continue to use the last complete refresh generation. On first load, the UI shows the staged pages as they arrive and indicates that the catalog is still filling. If that first attempt fails while the server is reachable, keep its staged pages on screen, say that the catalog is incomplete and offer Retry.

A walk is complete only when the number of unique item IDs it received, before any entry is skipped, equals the last response’s `total`. When the counts differ, refetch the whole library once as a single `limit=0` request. Its one response replaces the walked pages as the listing. If that request fails, the attempt has failed. Once the walk is complete or that refetch succeeds, use one Room transaction to check that this attempt is still the newest refresh for its profile and library, publish its membership and metadata, and advance the last-successful-refresh time. A successful empty result clears that library’s remote listing. A failed page or a superseded attempt leaves the published listing and timestamp intact. Discard only that attempt’s staging rows. A failed first load is the exception: its staged pages stay on screen until Retry starts a new attempt. Removing a remote listing preserves the local edition and saved position.

## Download lifecycle

| State | Visible actions | Transition |
|---|---|---|
| Available | Download | Read a fresh manifest, check permissions, format support and space, enqueue. If no address answers, start no transfer and show the unreachable-server copy, or the local-network or certificate-changed copy when one of those blocks an address. While the session is expired or signed out, start no transfer and show the session-expired copy. A download denial or unsupported manifest found here creates no job. |
| Queued or transferring | Pause, cancel | Write temporary files and journal progress. User pause persists across relaunch. |
| Waiting for connection | Retry, pause, cancel | Resume on a usable paired route after source-identity reconciliation, unless the user paused. Complete verified files that the refreshed manifest still identifies are reused, never restarted. |
| Paused or recoverable failure | Resume or retry, cancel | Reopen staging and verify source identity before continuing. |
| Verifying | Show status | Verify sizes and manifest, build local timeline, publish one generation. |
| Ready | Play or resume, remove | A local session may start. Removal keeps the progress record. |
| Repair needed | Repair download, remove | Stage a fresh generation. Preserve the saved book position. |

Transient failures retry with capped exponential backoff and a per-book attempt count, shown in the Paused or recoverable failure state. A download denial or unsupported manifest met after the job is enqueued, and the persistent mismatch of step 4, stop automatic retries at once. The job rests in Paused or recoverable failure, shows its failure category, and keeps its staged files. It continues only on an explicit Resume or Retry, which reads a fresh manifest first and so serves as the refresh action of step 1. Cancel reclaims its staging generation. A stopped repair or replacement leaves the published edition and its state as they were. Paused work stays paused across retries, process death and address changes.

A Cancel command names the job ID it was issued for and affects only that job. If cancellation commits first, the transfer remains cancelled across relaunch and its unfinished generation is reclaimed. If publication commits first, the book is Ready and the listener can remove it explicitly. A delayed Cancel command leaves the published edition and any later job intact. A repair attempt that fails must preserve any usable previously committed edition.

Keep one book transferring at a time and queue additional books. A per-book uniqueness constraint attaches duplicate requests for the same book to its existing job. A user-paused book yields the slot to the next queued book and resumes when the listener resumes it. The owner chose one at a time for v1.

### Safe continuation across routes

1. Capture the ordered playable source list, lengths and revision evidence (for example file ID, size and modification time). Join audio files to the server’s play order. Disabled tracks, artwork and ebooks cannot silently become audio files. An ambiguous join fails with a refresh action.
2. Preflight the book’s remaining bytes plus a margin of 1 GB: start or continue a transfer only while the volume’s free space is at least that sum, and check again before each file. Below it, the job rests with the storage-full copy, which names the shortfall. When the total is unknown, require the margin alone, show bytes received and handle a write failure by preserving safe partials. Check free space again before any replacement that requires a second copy.
3. Bind each partial to a fingerprint of the effective download URL, the source revision and a resume validator. The validator is a strong entity tag when the response carries one. Audiobookshelf v2.38.0 serves files through Express `res.download`, which honors `Range` but sends only a weak `ETag` and `Last-Modified`, and a weak tag is not allowed in `If-Range`. Without a strong tag, keep no entity tag and use the `Last-Modified` date as the validator, but only when the response’s `Date` is at least 60 seconds later, which makes the date a strong validator. Send `Accept-Encoding: identity` so local file offsets map directly to HTTP byte offsets. Before resuming, refetch the item and require the same `ino`, size and `mtimeMs` as the staging manifest. For the same URL and revision with a saved validator and known length, send one byte range and that validator in `If-Range`. Otherwise start from zero. Accept a single-part 206 only when the response still carries the saved validator, no content coding was applied, and `Content-Range: bytes start-end/total` satisfies `start == localLength`, `start <= end < total` and `total == expectedLength`. Check that the body delivers exactly `end - start + 1` bytes before accepting the response as complete. A valid range ending before the last byte leaves the file partial. A malformed response leaves the preceding usable prefix intact. A full 200 replaces the partial from byte zero.

   When the URL changes, refresh the manifest on the new route. Restart the partial track by default, even if the two URLs report equal ETags and sizes. A cross-route resume requires independent byte-identity evidence, such as a trusted whole-file digest for the same revision that the assembled file must match before publication. Reuse complete validated files when the refreshed manifest still identifies the same source.
4. On a 416, reconcile the expected size and source version. Treat a fully verified file as complete, otherwise restart it. On a 404 for a track, refetch item details once. If the manifest changed, stage that revision coherently. A mismatch that persists after that reconciliation stops the job in Paused or recoverable failure, as the [download lifecycle](#download-lifecycle) describes.
5. Check expected length or a trusted digest when supplied. For unknown lengths require a successful, complete transport and validate the local media through the selected parser before committing. Reject unexpected HTML/login responses, empty audio, truncated transfers and out-of-scope redirects. With the server’s `USE_X_ACCEL` option enabled, the file and cover routes answer 204 with an `X-Accel-Redirect` header and rely on nginx to send the bytes. A 2xx response without audio is a server configuration error, never an empty track. It stops the job as an unsupported manifest does and shows the no-audio copy from the [product brief](01-product.md#copy-and-recovery). Probe each local track’s actual container and codec before marking it playable. A track that the player cannot open stops the job as an unsupported manifest does, with the unsupported-format copy from the [product brief](01-product.md#copy-and-recovery), as [media format acceptance](05-playback-and-formats.md#media-format-acceptance) describes. Verify the resulting timeline before publication.
6. After a process restart, compare persisted offsets with disk and run publication recovery. A notification, UI double-tap, OS retry or route switch must still result in one completed book. See the [persistence and recovery rules](03-android-and-data.md#persistence-and-recovery-rules).
