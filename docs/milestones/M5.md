# M5 report: sleep and the layout pass

## Delivered

- Timed sleep uses elapsed time at every playback speed. Expiry during an interruption prevents automatic resumption. A timed stop keeps its place and applies the five-minute rewind after the rest threshold, including after a new process starts.
- End of chapter clips the current track at an in-track boundary. The player keeps whole-book time by placing silence beyond the cut until the pause takes effect. The service restores the full source at the exact boundary. At a track transition and the end of the book, the regular playback boundary owns the stop.
- Player sheets preserve their selection and open state across rotation. They open expanded and scroll when the available height is short. Playback progress stays within the edition duration.

## Emulator evidence

Both targets are the Pixel 7 images from [M0](M0.md#3-builds-tests-and-targets), running Media3 1.11.1. The sleep suite used the Android keyguard. JDK 21 and Gradle 9.8.2 built the APKs. Timed tests advanced an injected clock, and chapter and track tests rendered the fixture audio.

During the first sleep runs, emulator media clocks reported in-track stops about 110–140 ms beyond the chapter boundary. Scheduling the pause earlier still gave inconsistent position readings. The clip ensures the following chapter has no audio to play while the pause reaches the renderer. A separate book-end run reported a media-clock position after the edition duration. The app now binds the displayed book position to the verified duration.

## Reproduce

Build the two APKs using JDK 21. On a disposable emulator with the swipe lock screen enabled, run `SleepPlaybackTest` and `PlaybackFailureTest` via `am instrument -w -e class` and the AndroidJUnitRunner. For A08 and A22, enable airplane mode and disable Wi-Fi. Run the A08 method with `-e offline true -e offlineRestart true`, then run `RestartTest#a22OfflinePlaybackKeepsItsPlaceAndSpeedAfterProcessDeath` in a separate instrumentation process. Restore the emulator network and lock settings afterwards. Run the two `RestartTest#a12bPart…` methods in separate instrumentation processes with `-e sleepRestart true`. The first writes a marker and the second checks it in the new process.

Run `VisualChecksTest` and `LargeTextScreensTest` at the compact and wide sizes. The layout checks use actual Compose semantics and device display settings.
