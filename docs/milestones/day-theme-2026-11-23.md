# Follow-up report: one theme

Date: 23 November 2026. Target: the owner's request after trying dark mode on the phone: “The app is essentially broken in dark mode, it looks terrible. I think we should not support dark mode in this way, but instead show the default, designed theme everywhere, and then maybe introduce different themes where every color is properly adjusted in the future.” The plan changed in the same commit.

## 1. Delivered

- The app, its dialogs and sheets, its window and the home screen widgets use the day palette whether the phone is light or dark. The night palette, the night paper and the night resources are gone.
- Android's status and navigation bars draw dark icons over the paper in both modes.
- Android neither darkens nor inverts the app. With “Make more apps dark” on, Android inverts every window whose theme claims to be light, and `forceDarkAllowed` does not stop it. So the theme turns off `forceDarkAllowed` and does not claim to be light (`isLightTheme` false), although its colors are light. The [interface specification](../02-interface.md#type-color-and-layout) records the rule.

## 2. Files and design decisions

- `ui/theme/Theme.kt`: one palette. `PagewornTheme` no longer takes a dark flag, and `PagewornColors` no longer says whether it is dark.
- `res/values/themes.xml`: the window theme, with `isLightTheme` and `forceDarkAllowed` false. `values-night/` and `drawable-night/` are removed, and `pw_paper_night` is no longer bundled. The tile stays in `docs/art/` for a later theme.
- `MainActivity.kt`: both bar styles stay automatic, so Android keeps its scrim behind 3-button navigation, but never take the phone's dark mode for the app's.
- `ui/components/PaperScaffold.kt`: the paper tile and the page edges keep only their day values.
- The device tests that expected a darker app with the phone dark now expect the same paper: `LargeTextScreensTest.lightAndDarkPhoneKeepDayPaperLargeTextVisibleAndTargetsTouchable` and `VisualChecksTest.v04SheetsAnnounceSpeedAndTimerChoiceAndUtilitiesStayVisibleWhenThePhoneIsDark`.

## 3. Checks

The device checks ran on a new disposable AVD: Pixel 6 profile, Google APIs arm64, API 37, 1080 × 2400 at 480 dpi (360 × 800 dp, the owner's phone width). A private adb server that claimed no USB device kept the attached phone out of reach.
