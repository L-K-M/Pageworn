# M2 report: sign-in, pairing, failover, certificate trust, sign-out and the catalog

Date: 21 November 2026. Target: the [M2 exit check](../06-delivery-and-tests.md#milestones), against a local Audiobookshelf v2.38.0 reference instance with disposable non-admin accounts.

## 1. Delivered

- **Connection setup.** The address is normalized and checked before any credential is sent: an invalid address, a plain-HTTP address until the listener accepts the cleartext tradeoff for that origin, the local-network permission on Android 17 before the first contact, an unrecognized certificate with its SHA-256 fingerprint and Trust this certificate, an unreachable host, a server older than 2.26.0 and a server without password sign-in each show their own message under the address field. Wrong credentials, and a server that refuses more sign-ins for now, show theirs under the password. Nothing is stored until a sign-in succeeds.
- **One account, several addresses.** A second address pairs only with the same account, after a confirmation that names the account and a library it shares. Another account is refused with "This phone holds books for [account name]. Sign in with that account." and a server that holds none of the profile's libraries is refused as a mismatched pairing. Every address keeps its own session, tokens and certificate decision; nothing extends to another origin.
- **Routes and failover.** Automatic mode uses the first enabled, paired address that answers, in the listener's order, and remembers it per network. Manual mode uses only the pinned address. A certificate problem or a denied local-network permission blocks an address without contacting it, and when no address can serve, the first blocked address in order decides the message. Switching addresses keeps one book record.
- **Sessions.** Tokens live in files encrypted with a Keystore key, one pair per address, out of backups. An access token close to expiry is renewed before use, concurrent requests share one renewal, and a session that cannot be renewed marks its address signed out.
- **Sign-out and sign-in.** Sign out asks once, revokes the session of every address that answers and deletes every credential. The profile, its addresses, the cached catalog, editions and saved places stay. Library then shows "Sign in to refresh your library." over its cached rows.
- **The catalog.** A refresh walks every page, checks completeness against the reported total (one `limit=0` fetch when it does not add up) and publishes atomically, so a failed refresh never replaces the cached rows. Library shows the loading, incomplete, unreachable (with the last refresh), sign-in, certificate and local-network states as its status line, or in place of the rows when nothing is cached. Search and the library selector work over the cached catalog while the server is away.
- **Settings and Server addresses.** Settings names the account and offers Sign out or Sign in. Server addresses renames, reorders (with TalkBack and keyboard actions), enables, tests, pins and removes addresses, trusts a presented certificate, asks for the local-network permission and adds an address.
- **Launch.** Without a profile the app opens connection setup, and the first sign-in opens Library. With nothing downloaded and no cached catalog, a launch whose refresh is blocked opens connection setup in that state (unreachable, local network or changed certificate) with Retry, once.

## 2. Files and design decisions

- `server/`: `BaseUrl` (address normalization), `AddressHttp` (one OkHttp client per address), `AbsClient` (the pinned contract), `AddressSession` (tokens and renewal), `RouteSelector`, `LocalNetwork`, `KeystoreTokenVault`, `ServerError`.
- `account/`: `ServerAccess` routes work to an address and records what each request taught about it; `AccountService` is the application service for setup, pairing, sign-out, address management and refreshes.
- `catalog/`: `CatalogRefresher` stages, checks and publishes refreshes and reads the listing with its status.
- `ui/connect/`, `ui/settings/`, `ui/state/ConnectViewModel.kt`, `ui/state/AccountViewModels.kt`, `ui/state/LibraryViewModel.kt`, `ui/AppNavHost.kt`: the screens and their view models, which call `AccountService` and observe Room.
- **The HTTP client is the gate.** The network security configuration admits cleartext and the system and user authorities at application level, because the listener enters hosts at run time. Each address's client refuses any request outside its base URL, plain HTTP without that origin's opt-in, and a redirect that leaves the base URL or downgrades. A confirmed certificate is pinned by whole-certificate SHA-256 to its origin only.
- **Response bodies are read off the caller's thread.** The UI flow found that a sign-in from the main thread failed intermittently: OkHttp delivers the response headers on its own thread, and reading a body that was not yet buffered threw `NetworkOnMainThreadException`, which had no message and surfaced as "Can't reach your server." The client now reads and decodes on the IO dispatcher; `ServerClientTest.responseBodiesAreReadOffTheCallersThread` failed before the fix and passes after it.
- **The server limits sign-ins.** Audiobookshelf v2.38.0 allows 40 sign-ins and session renewals per 10 minutes from one client address and then answers 429. The M2 check found it when two runs in a row spent the budget, and the app showed "Can't reach your server." A 429 is now its own error: sign-in says "Too many sign-in attempts. Try again in a few minutes." and a renewal keeps its session. The reference instance keeps the default limit; `m2-check.sh` reads the remaining budget from the server's `RateLimit-*` headers and waits for the window when a run would not fit.
- **Plan changes in this milestone.**
  - [Product brief](../01-product.md#copy-and-recovery): the copy for a mismatched pairing, an invalid address, wrong credentials, the cleartext tradeoff, the local-network request and the pairing confirmation (`9c5ba17`), the too-many-sign-ins copy, and the rule that the first sign-in opens Library.
  - [Interface](../02-interface.md): in Server addresses, a blank label keeps the previous one, Remove revokes that address's session, and removing the last address keeps the profile, catalog, downloads and places.
  - [Server contract](../04-server-and-downloads.md#observed-on-the-reference-instance): `POST /logout` ends that session's refresh token; the Android 17 emulator blocks the host alias `10.0.2.2` without `ACCESS_LOCAL_NETWORK`; the limit on sign-ins and renewals, and what a 429 means to the app.
