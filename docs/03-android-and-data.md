# Android architecture and durable state

## Runtime ownership

Use a single Android application module to start. Organize by feature or by the boundaries below, following the host repo’s conventions. Use Kotlin coroutines and immutable UI state. The UI observes Room and the playback controller. A composable going off-screen must never cancel an intentional book download or a sleep timer.

| Boundary | Owns | Exposes |
|---|---|---|
| Compose screens and ViewModels | Navigation, input, transient selection, presentation of errors | User intent such as download, resume, remove or set sleep |
| Catalog and address resolution | Account-scoped catalog refresh, approved origins, route choice, authentication | Paged book summaries, last successful refresh, manifest acquisition |
| Transfer coordinator | Durable queue, partial files, retries, one active job per book | Per-book progress and a verified local edition |
| Media library service | Local playback engine, audio focus, headphone, lock-screen and car commands, sleep deadline, the car’s list of downloaded books | One source of live player state for system controls, Android Auto and UI |
| Book timeline and progress store | Time conversions, chapter lookup, checkpoints, finished state | Resume position and status for each book |
| Persistence | Room for structured state, app-private storage for media, Keystore-backed token encryption | Transactional updates and recoverable files |

Start with Compose Navigation, Room, OkHttp, a JSON decoder tolerant of unknown fields, and AndroidX Media3. Use the repo’s dependency catalog and pin resolved versions. Inject a clock, local file store and network transport where tests need deterministic faults. The player takes only committed local file handles. Keep HTTP libraries outside its playback data path.

## Identity and schema

Treat server IDs as opaque strings. Use 64-bit integers for times in milliseconds and for byte counts. Use a local profile UUID as the stable root for one server and account. A URL identifies a route. The book key is `(profileId, itemId)`, including when library metadata changes or titles collide.

| Record | Keys and minimum fields | Lifetime |
|---|---|---|
| Profile and Address | Profile ID, server account ID and account name, pairing evidence, chosen library. Address ID, profile ID, normalized origin and path prefix, label, priority, enabled, last success, credential reference, cleartext opt-in, confirmed certificate fingerprint | Pairing an alias adds an address to the profile. Token material stays out of Room. |
| Library and CatalogBook | Profile and library ID, item ID, title, author, narrator, artwork cache key, duration, last refresh generation | Refresh a complete generation before removing stale remote entries. Downloaded editions survive catalog changes. |
| LocalEdition | Book key, revision fingerprint, generation ID, state, duration, private relative directory, cover reference | Exactly one published generation per book. Stage a replacement separately until verified. Snapshot display metadata with the edition. |
| Track and Chapter | Generation ID and ordinal, source file ID, source revision, file size, local filename, start and duration. Chapters store title, origin, start and end | A generation pins ordering, offsets, chapter map and media bytes together. Chapter rows can span track boundaries. |
| Transfer | Book key, job ID, staging generation, manifest fingerprint, state, failure category, per-file byte count, effective download URL fingerprint and validator | Unique active job per book. Workers reopen by ID and reconcile the journal with actual file lengths. |
| BookProgress | Book key, absolute position, duration at save, edition fingerprint, finished flag, update time, stop kind | Retained on transfer cancellation and audio removal. A new item with the same title has a different key. |
| Playback settings | Last active book, chosen speed, last destination, theme preference if exposed | Lightweight preferences. A timed sleep request belongs to the active playback service. |

Keep source metadata, credential material and display metadata separate. A published edition keeps the display metadata snapshotted at verification time, while Library rows show the last complete catalog refresh, or the staged pages of a first load. After a server-side metadata edit the two can differ until the edition is re-downloaded (see A11). Only materially changed audio affects playback continuity, as rule 7 describes. A metadata edit never does. Avoid storing server absolute filesystem paths. Generate local paths from internal IDs and sanitized file extensions. Keep audio under persistent app-private storage, outside cache and OS backup. Exclude credentials and device-bound transfer state from backup. Cache artwork can be evicted. Copy the cover into the committed edition so Downloaded and the player still render offline.

Define the edition fingerprint as a digest of the ordered source file IDs, sizes and modification times and the ordered track durations. LocalEdition stores it as its revision fingerprint and BookProgress records it at save. Cover, title, author, description and chapter edits leave it intact. Reordering, replacing or re-encoding audio changes it. Rule 7 uses this fingerprint to tell a metadata refresh from a material audio change. A transfer’s manifest fingerprint identifies the source list of one job and is a separate value.

## Persistence and recovery rules

1. Enqueue under a unique book key. Repeated taps attach to the existing transfer. Journal file lengths for display, but use the bytes on disk when deciding where to resume. Keep one book transferring at a time. A user-paused book yields the slot to the next queued book and resumes when the listener resumes it.
2. Write all audio, a compact manifest, and optional cover to a staging directory on the same volume as the final edition. Missing artwork uses the cloth fallback. Missing mandatory tracks keep the edition in staging.
3. Verify every file as defined in the [transfer contract](04-server-and-downloads.md), finish the chapter map, and atomically rename the directory. In one Room transaction, verify that the job ID and generation still match the book’s current transfer, the transfer is verified and not cancelled, and removal is not pending. Then point the published edition at that directory, install its track/chapter rows, and mark the transfer complete. The filesystem rename and the database transaction have separate failure boundaries.
4. On startup or before opening a book, recover an interrupted publish from the finalized manifest and generation ID using the same transaction checks. A finalized directory alone grants no authority to publish. Promote only a complete matching generation. Persist cancellation before acknowledging it or deleting files. A cancelled or superseded worker cannot publish, and cleanup reclaims only that job’s unreferenced generation after its writer has stopped. A missing published file changes state to Repair needed while keeping progress.
5. During replacement, readers keep using their current edition until playback releases it. Clean up a superseded generation after no session holds it. For explicit removal, pause the book, checkpoint, mark removal pending, delete audio, then clear the edition rows. Retry unfinished cleanup after process death. A second removal is harmless.
6. Save immediately on pause, seek, book switch, timer expiry and completion, and record with each save how the book stopped, for the [resume rewind](05-playback-and-formats.md#resume-rewind). During continuous playback, commit a checkpoint at least every five seconds of media advancement. At 2× speed this allows at most 2.5 seconds of elapsed time between commits. Serialize writes from the service by book and playback generation. A delayed callback from the previous book or generation must never overwrite newer progress. Within the same book and playback generation, invalidate pre-seek position samples when a seek starts. After the seek completes, commit its resolved position before accepting further periodic samples from the new playback position. A queued checkpoint from before a rewind cannot undo it.
7. For the same edition, restore the saved time, clamp to duration and apply the resume rewind. For reordered or materially changed audio after re-download, retain the old position and offer **Use previous position** or **Start over** before first play. Show the old time and new duration. A cover or description edit alone leaves playback continuity intact.

Serialize removal with playback startup for the same book. When marking removal pending, invalidate any unpublished transfer for that book in the same Room transaction. While removal is pending, block new playback and downloads for the book. Release all readers before deleting the audio. After process death, resume pending removal before publication recovery for that book.

## Android integration

- Use a `MediaLibraryService` with a `MediaLibrarySession` for playback, so that Android Auto can list the downloaded books and the system can offer its resumption control. Export the service with the intent-filter actions `androidx.media3.session.MediaLibraryService` and `android.media.browse.MediaBrowserService`. Declare `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, and set the service’s `foregroundServiceType` to `mediaPlayback`. Declare `POST_NOTIFICATIONS` and request it before relying on a completion notification. Media-session notifications are exempt from that permission. The activity binds via a controller and releases it on lifecycle changes. Declare Media3’s `MediaButtonReceiver` with its `android.intent.action.MEDIA_BUTTON` intent filter so a Bluetooth headset Play can restart the service, as [system controls and resumption](05-playback-and-formats.md#system-controls-and-resumption) describes. Only a user play action starts or resumes audible playback, apart from the resume after a transient interruption that the [playback contract](05-playback-and-formats.md) defines.
- Declare Android Auto support with the `com.google.android.gms.car.application` meta-data entry and an `automotive_app_desc.xml` resource that names `media`. The [car rules](05-playback-and-formats.md#android-auto) define what the service serves and to whom.
- Downloads are user-initiated, durable work. Run each as a user-initiated data transfer job, which every supported Android version offers. It is a JobScheduler job, so it needs `RUN_USER_INITIATED_JOBS` and no foreground-service type, can be scheduled only while the app is visible, requires a network of any type, and must post its own progress notification within ten seconds of starting. A stopped job recovers its transfer through the recorded state under platform scheduling rules. If the platform refuses to schedule a job because the app is not visible, keep the transfer state visible in Downloaded and resume the work the next time the app is in the foreground.
- A denied notification permission never blocks a transfer, a download state or local playback. Show status inside the app. The first time a download is enqueued while the permission is denied, show the notifications-disabled copy from the [product brief](01-product.md#copy-and-recovery) with an action that opens the app’s notification settings. It stays until the listener uses the action or goes from Downloaded to another screen, and does not return. Media-session notifications are exempt from the permission, so the media controls still appear and the session still receives lock-screen and headphone commands. While the permission is denied, the system keeps a transfer’s notice out of the notification drawer and may still list the transfer in its Task Manager.
- Keep audio, editions, credentials and device-bound transfer state out of OS backup with `android:dataExtractionRules`. The simplest rule that satisfies this is the one implemented: Pageworn backs up nothing. `android:allowBackup` is false and the extraction rules exclude every domain from cloud backup and device transfer, because the profile, catalog and saved places mean nothing without the audio and credentials. Cache directories are never backed up, so cache artwork needs no rule and can be evicted. Keep tokens encrypted using a key protected by Android Keystore. Replace refreshed token pairs together. Redact credentials, URL queries and book filenames from network diagnostics. Reauthentication leaves local media accessible to the paired profile.
- The app targets SDK 37. On Android 17, local network access is blocked by default for such an app and needs the `ACCESS_LOCAL_NETWORK` runtime permission, which belongs to the nearby-devices group. Declare it. On Android 14 to 16 the permission does not exist and local access is unrestricted, so the app requests nothing there. Android’s definition of a local network includes 100.64.0.0/10 and excludes VPN connections, so whether a Tailscale address needs the permission is recorded on the listener’s phone as an [owner check](06-delivery-and-tests.md#owner-checks), never assumed.
- Ship a network security configuration that trusts the system’s certificate authorities and the ones the listener has installed on the phone, and that allows cleartext at application level. The configuration is fixed at build time and the listener enters hosts at run time, so the HTTP client is the gate. It sends cleartext only to an origin with a stored opt-in. It accepts a certificate outside the trust anchors only from the origin whose confirmed fingerprint that certificate matches, as the [transport rules](04-server-and-downloads.md#a-profile-can-have-several-addresses) require. Build that exception into one trust manager that hands every other origin to the platform’s validation. Never let a cleartext allowance or a confirmed certificate weaken validation for any other origin or send credentials to an unpaired destination.
- Export diagnostics through the system’s create-document dialog, which needs no storage permission. The file is plain text: the app version, the Android version and the redacted network log, with each address named by its label.
- Build the open-source notices from the dependency graph with a plugin that needs no Google Play services, and add Spectral’s copyright notice and licence text.
- Migrate the Room schema additively. Run an upgrade test with an existing download and saved place before shipping a schema change. A schema mismatch must never trigger silent deletion of the listening library.
