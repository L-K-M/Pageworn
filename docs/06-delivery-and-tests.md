# Delivery sequence and acceptance tests

Build one end-to-end behavior at a time. A milestone is complete when its checks run on the stated target and the result is recorded. Label unavailable hardware or server checks as pending. The implementor has emulators and a local reference server only, so run each check there as far as it goes, and report the part that needs the listener’s phone, car or server as a pending [owner check](#owner-checks). Keep later work independent of the availability of personal credentials by using a sanitized contract fixture and a local test server.

### M0 build and test baseline

- If the repository has no Android project, initialize the single-module project at the repository root with the application ID `ch.lkmc.pageworn`, minimum SDK 34, and compile and target SDK 37. Check in the Gradle wrapper and pinned build and dependency versions. Record the JDK and Android SDK requirements and the build, install and test commands so a fresh checkout can reproduce the spike.
- Add the CI workflow of [build, CI and release](#build-ci-and-release) with the project, so that every later push is built and tested.
- Build, install and exercise the playback service using local fixtures on two emulator targets: API 34 and API 37, the original minimum and the listener’s Android 17. Record the image and API level of each. If no API 37 image can be installed, use API 36 as the current target and leave the cases that need Android 17 pending. The reference seek uses the Boundary book defined below.
- The listener’s server runs Audiobookshelf 2.38.x, so the target is the reference release v2.38.0 that the [server contract](04-server-and-downloads.md#server-contract-to-pin-in-m0) pins. Inventory that release’s scanner and use a local instance with a disposable account to check sign-in and capture the sanitized track-to-download mapping. Record the release and distinguish observations from the reference instance from checks against the listener’s deployment. The implementor has no access to that deployment or to the listener’s phone, so every check that needs either one stays pending as an [owner check](#owner-checks).

### Android 12 compatibility

Android 12 (API 31) is the minimum supported version. On API 31, verify the
install, format matrix, local playback and the download queue against the
reference server. Exercise background continuation, completion notifications
and restart recovery. Recheck the JobScheduler path on API 34.

### Build, CI and release

- **CI.** A GitHub Actions workflow builds the debug app and runs the JVM tests on every push. Instrumented tests run on the emulators of the machine that builds the milestone, and the milestone report records them.
- **Release.** A second workflow runs on a version tag such as `v1.0.0`. It builds the release variant with code shrinking on, signs it and attaches the APK to a GitHub release for that tag. The version name is the tag, and the version code rises with every release. The release notes say that Android Auto shows the app only after its unknown-sources developer option is turned on.
- **Signing key.** The owner creates the release keystore and adds it to the repository as encrypted secrets: the keystore file in base64, its password, the key alias and the key password. The key never enters the repository, a log or a build artifact. Until the secrets exist, the workflow fails with a message that names the missing secret. The key must stay the same for every release, because Android refuses an update that is signed with another key.
- **Notices.** Generate the open-source licence list from the build’s dependencies and show it under Settings together with the Spectral licence. The repository’s own code and art are in the public domain under the Unlicense.
- **No telemetry.** The app sends no crash reports and no analytics. The only log leaves the phone when the listener exports diagnostics.

## Fixtures a contributor can reproduce

- **Boundary book (`boundary-book`).** Generate two tracks of 90 s and 120 s with distinguishable audible cues. Start a cue 250 ms after every point between the book’s start and its end where a track ends or a chapter of any supplied chapter list starts or ends, so a stop beyond the 100 ms tolerance is audible as well as measurable. Supply three server chapters at 0, 75 and 140 s. Keep the end at 210 s. Use this fixture for cross-track seek, independent chapter boundaries and chapter sleep. Keep the alternate server chapter lists that A28 and A28b name beside it. Tests can serve its tracks through the fault-injecting file store to fail a track’s open, or to fail or delay a read at a chosen position once or repeatedly.
- **Single M4B (`single-m4b`).** One DRM-free AAC M4B of 300 s with three embedded titled chapters at 0, 100 and 200 s and a cover. Supply a second server chapter list with edited titles and two chapters, 0–120 s and 120–300 s, to prove that server edits win and that embedded markers are never mixed in. Repeat with the server list removed to exercise embedded fallback.
- **No chapters (`no-chapters-single`, `no-chapters-multi`).** A single-file book and a multi-file book with no markers. Build the multi-file book from the boundary book’s two tracks without a chapter list, so its first track ends at 90 s. Include missing artwork and narrator, a long title, two authors, and two distinct item IDs with the same title.
- **Formats (`fmt-` plus family and variant, such as `fmt-mp3-vbr-long`).** Generate short samples for the [format matrix](05-playback-and-formats.md) and at least one VBR MP3 of 20 minutes or more (`fmt-mp3-vbr-long`) with identifiable cues near the end. Keep generation commands, tool versions, checksums and redistribution rights with the fixtures. Generate large audio locally instead of adding hours of binary media to Git.
- **Fixture manifest.** Keep a machine-readable manifest beside generated fixtures with the fixture ID, generation command, tool and version, container, codec, duration, checksum, redistribution right and, for format samples, the server release that admitted it. Tests reference fixtures by ID rather than by a machine-specific path. The IDs given in this list are the manifest keys. Acceptance cases name a fixture in words or by its manifest ID.
- **Network (`network`).** Serve a sanitized catalog from a controllable HTTP fixture with two origins, at least one on a local-network address, and optional path prefix. Include two libraries with different page counts, per-page failure and delay controls, paginated results, an empty library, an account with no accessible book libraries, a mixed-media item, denied download, token rotation, mismatched account/library IDs, a self-signed certificate, a certificate from a private authority that the test device trusts, a certificate that is replaced between two runs, a recorder for `POST /logout`, 200/206/416 responses, a transient 5xx, a track that keeps returning 404 while its item still lists it, an item whose audio files cannot be joined to its play order, a content-coded 206, truncated bodies, incompatible entity validators, and a second-route response with the same size and ETag but different bytes. Reproduce the v2.38.0 behaviors the transfer contract relies on: a weak `ETag` with `Last-Modified` and a controllable `Date`, a 1-hour access token, a replaced refresh token that stays valid for a grace period the fixture controls, a refresh whose response is lost after the rotation, a library that gains an item during a page walk, a body-less 204 with `X-Accel-Redirect`, an ebook-only item, an excluded audio file, an item with a track in an unsupported codec, an item whose track is labelled MP3 but cannot be opened, a `limit=0` catalog request that returns the whole library, a status response from a release older than 2.26.0 and one without the `local` sign-in method. Run at least one full smoke test against the pinned Audiobookshelf version.

## The listener’s deployment

The owner gave these facts on 21 November 2026. They settle the questions that the plan used to leave for M0.

| Fact | Consequence |
|---|---|
| The server runs Audiobookshelf 2.38.x. | The reference release v2.38.0 is the target. The app still enforces 2.26.0 as its minimum. |
| nginx sits in front of the server. | Whether nginx changes the file validators, and whether the server runs with `USE_X_ACCEL`, are owner checks. The [range rules](04-server-and-downloads.md#safe-continuation-across-routes) hold either way: a missing validator costs a restart from byte zero, and a response without audio stops with the no-audio copy. |
| Sign-in is by username and password. | OpenID Connect stays outside v1. |
| The addresses use HTTPS with a public certificate, HTTPS with a self-signed or private-authority certificate, and plain HTTP at home and over Tailscale. | All three transports are in scope: normal validation, a confirmed certificate and the per-origin cleartext opt-in. |
| The phone runs Android 17. | API 37 is the current test target, and the local-network permission applies. |
| Listening goes through Bluetooth headphones and speakers, a car over Bluetooth, Android Auto and wired headphones. | The playback service is a media library service with a list for the car. |
| The library holds M4B, M4A, MP3, FLAC, Opus and Ogg files. | These formats must pass the matrix. Any other family may end up unsupported. |
| The implementor has no access to the server or the phone. | Development and automated checks use the emulators and a local reference server. |

## Verification and handoff

Use JVM tests for timeline math, identity, route selection, timer decisions and transfer response handling. Use an instrumented app for Room/file recovery, service lifecycle, Compose semantics and media controls. Use a physical phone for Bluetooth, locked-screen sleep, real network switching and audible seek accuracy. The implementor works with emulators and a local reference server only, so each of these is an [owner check](#owner-checks). Before publishing an Android compatibility claim, record the OS/API, device, codec and result. Emulator-only checks should be identified as such.
