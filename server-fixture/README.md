# server-fixture: local Audiobookshelf reference instance

A reproducible local Audiobookshelf **v2.38.0** server with disposable
accounts, used to pin the server contract that the Pageworn Android client
relies on. `capture.py` records the API exchanges and writes sanitized JSON
fixtures into `app/src/test/resources/abs/v2.38.0/` for unit tests.

Everything is disposable: random passwords on every seed, named Docker
volumes for all state, and `server-fixture/.state/` holds only
`accounts.json` (credentials + created IDs for capture).

## Requirements

- Docker (runs against Colima; the image
  `ghcr.io/advplyr/audiobookshelf:2.38.0` is pinned)
- Python 3 (standard library only)
- Fixture audio at `fixtures/out/assets/fixtures/<id>/` (generated by the
  repo's fixture generator; `manifest.json` lists the ids)

## Usage

```sh
server-fixture/abs.sh up        # start pageworn-abs on http://127.0.0.1:13378
server-fixture/abs.sh seed      # root init, users, libraries, files, scans
server-fixture/abs.sh capture   # write app/src/test/resources/abs/v2.38.0/*.json
server-fixture/abs.sh down      # stop + remove the container (volumes stay)
server-fixture/abs.sh reset     # down + remove volumes + delete .state
```

`seed` creates:

- libraries: `Audiobooks` (book) on `/audiobooks`, `Second shelf` (book) on
  `/second`, `Podcasts` (podcast, empty) on `/podcasts`
- users: `listener` (download=true, all libraries), `browser`
  (download=false), `nolibs` (librariesAccessible=[])
- books: `The Night Orchard` (single m4b with embedded chapters),
  `Boundary Book` (2 tracks + server chapters 0-75/75-140/140-210),
  `Field Notes on Rain` (multi-file, no chapters), `Small Hours`
  (single file, no chapters), two `Same Title` books, `WMA Book`
  (wmav2), `Mislabelled Book` (AIFF audio named `.mp3`), `Mixed Media
  Book` (m4a + epub), `Exclude Track Book` (3 files, middle file
  `exclude: true` via PATCH tracks). A library scan after the seed clears
  that exclusion; set it again as `seed.py` does.

## A second, HTTPS origin

`tls_proxy.py` terminates TLS on `127.0.0.1:13443` and forwards to the
plain instance, so one server answers on two origins (the emulator sees
them as `http://10.0.2.2:13378/` and `https://10.0.2.2:13443/`). It
generates a self-signed certificate per name under `.state/tls/` and
prints its SHA-256 fingerprint. Restart it with another `--cert` name to
present a changed certificate:

```sh
server-fixture/tls_proxy.py --cert first     # unrecognized certificate
server-fixture/tls_proxy.py --cert second    # the certificate changed
```

## Transfer faults

`fault_proxy.py` forwards plain HTTP to the instance one request per
connection and injects the transfer faults the download checks need: a body
dropped after N bytes, an ignored `Range`, a throttled body, an error status,
or a connection closed without an answer. A JSON control port sets the rules
and reads a log of the requests (method, target, `Range`, `If-Range`, the
fault applied, status and body bytes so far; never other headers or
bodies). `fault_proxy_selftest.py` checks it against a local stand-in server.

```sh
server-fixture/fault_proxy.py --listen 13380 --backend 13378 --control 13390
curl -X POST --data '[{"mode":"drop","bytes":100000}]' http://127.0.0.1:13390/rules
curl http://127.0.0.1:13390/log
server-fixture/fault_proxy_selftest.py
```

`m3-check.sh <emulator-serial>` runs the M3 exit check
(`DownloadIntegrationTest`): it starts two proxies, "Home" on 13380 and
"Remote" on 13381 (control ports 13390 and 13391), and between phases turns
airplane mode on and off and kills the app's process mid-transfer. Phase 6
fills the emulator's data volume with a preallocated file in the app's
files directory, grows it again whenever the platform purges cached data to
make room, and deletes it at the end. `ONLY="phase6 phase8"` runs only the
named phases. Before phase 5 on a disposable API 31 emulator, run
`adb -s <emulator-serial> root` so the host can signal the app process.

## Why named volumes instead of bind mounts

Docker on macOS often runs inside a Colima VM whose bind mounts of host
paths on external volumes can go stale (the VM does not see files created
on the host). `abs.sh up` therefore mounts named volumes
(`pageworn-abs-{config,metadata,audiobooks,second,podcasts}`) and `seed.py`
stages the library tree in a temp dir and pushes it into the running
container with `docker cp`, then `chmod -R a+rX` inside the container.
`abs.sh reset` removes the container and all five volumes.

## Observations on v2.38.0

- `GET /status` (no auth): `{app: "audiobookshelf", serverVersion: "2.38.0",
  isInit, language: "en-us", authMethods: ["local"], authFormData}`.
  `isInit` is `true` once a root user exists.
- `POST /login` + header `x-return-tokens: true` → 200
  `{user, userDefaultLibraryId, serverSettings, ereaderDevices, Source}`.
  `user.id`, `user.username`, `user.permissions.download` (bool),
  `user.accessToken` and `user.refreshToken` are on `user`; a legacy JWT
  also sits in `user.token`. Without the header the refresh token goes into
  a `refresh_token` cookie and `user.refreshToken` is `null`.
- Access-token `exp - iat` = **3600 s**; refresh-token = **2 592 000 s
  (30 days)**.
- `POST /auth/refresh` with `x-refresh-token` rotates the refresh token.
  Immediately retrying with the **old** refresh token still returns **200**
  (grace period): the response carries the already-rotated refresh token
  plus a fresh access token.
- `GET /api/libraries` → `{"libraries": [...]}`; a book library has
  `mediaType: "book"` (`"podcast"` otherwise). Entries carry `id`, `name`,
  `folders`, `displayOrder`, `icon`, `provider`, `settings`, `lastScan`,
  `lastScanVersion`, `createdAt`, `lastUpdate`. `nolibs` gets 200 with
  `{"libraries": []}`.
- `GET /api/libraries/{id}/items` → `{results, total, limit, page, sortBy,
  sortDesc, mediaType, minified, collapseseries, include, offset}`.
  **`limit=0` returns all items** (9 books came back in one page).
- Expanded `media.tracks[]` fields: `index`, `ino` (**string**),
  `metadata{filename, ext, path, relPath, size, mtimeMs, ctimeMs,
  birthtimeMs}`, `trackNumFromMeta`, `trackNumFromFilename`, `discNum*`,
  `manuallyVerified`, `exclude`, `error`, `format`, `duration`, `bitRate`,
  `language`, `codec`, `timeBase`, `channels`, `channelLayout`, `chapters`
  (per-file embedded chapters), `embeddedCoverArt`, `metaTags`, `mimeType`,
  `title`, `startOffset`, `contentUrl` (`/api/items/{id}/file/{ino}`).
- The excluded file is **absent from `media.tracks`** (tracks re-indexed
  1..n) but **still present in `media.audioFiles`** with `index: -1` and
  `exclude: true` (`numTracks: 2` vs `numAudioFiles: 3`). Set via
  `PATCH /api/items/{id}/tracks` with `{orderedFileData: [{ino, exclude}]}`,
  echoing `ino` with the JSON type the server returned (string).
- `media.chapters` is `[{id, title, start, end}]`. Server-set chapters
  (`POST /api/items/{id}/chapters`, needs update permission) are returned
  verbatim. For the chapterless **multi-file** book the server
  *synthesizes* `media.chapters` per track with cumulative offsets titled
  by filename (`01-part` 0-90, `02-part` 90-210), not an empty list. For the
  chapterless **single-file** book `media.chapters` is `[]`.
- The single-m4b book exposes its **embedded chapters** both in
  `audioFiles[0].chapters` and merged into `media.chapters` (0-100,
  100-200, 200-300).
- WMA book: `codec: "wmav2"`, `format: "ASF (Advanced / Active Streaming
  Format)"`, `mimeType: "audio/x-ms-wma"`.
- `GET /api/items/{id}/file/{ino}/download` → 200 with
  `content-type: audio/mp4`, `content-disposition: attachment;
  filename="..."`, `content-length`, `accept-ranges: bytes`, weak **ETag**
  `W/"<hex>-<hex>"`, `last-modified`, `date`, `cache-control: public,
  max-age=0`, `content-security-policy: frame-ancestors 'self'`,
  `referrer-policy: no-referrer`. Body bytes sha256-match the fixture file.
  `Range: bytes=1000-` → **206** `content-range: bytes 1000-N/M`;
  `If-Range` with either the `Last-Modified` value or the `ETag` value also
  → **206**.
- `browser` (download=false) gets **403** `Forbidden` on `/download`, but
  **200** on the plain stream route `GET /api/items/{id}/file/{ino}`: the
  stream route only checks library access, not the download permission.
- `GET /api/items/{id}/cover?width=200&format=webp&ts=<updatedAt>` with **no
  token** → 200 `image/webp`.
- `POST /logout` with `x-refresh-token` → 200 `{redirect_url: null}`.

## Capture files

`app/src/test/resources/abs/v2.38.0/` holds one JSON per exchange
(`{request, response}` with headers; tokens → `<access-token>` /
`<refresh-token>`, `Set-Cookie` dropped, host → `server.example`, no
passwords). `login-browser.json` and `login-nolibs.json` are extra context
for the per-user captures.

### Playback and system controls

After building both APKs, run `server-fixture/m4-check.sh <emulator-serial>` on
a disposable Google APIs emulator. The `a16-noisy` phase temporarily switches
adbd to root for the system headphone-disconnect broadcast. `a16e-kill` sends
a media key after a background process kill. `restart` runs the progress
recovery checks. `repair` and `notifications` use the seeded reference server.
The notifications phase clears Pageworn’s app data to test a fresh denied
permission. Set `ONLY=restart` or another phase name to run it by itself.
